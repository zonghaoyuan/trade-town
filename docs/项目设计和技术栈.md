# 项目设计和技术栈

# 一、设计思路

在斯坦福小镇的基础上加上金融交易的元素，模拟事件发生对小镇的金融交易的影响。用户也可以自定义一个角色参与小镇并观察其交易。第一阶段使用持续标记为
`LOCAL SIM` 的本地市场完成自治 Demo；进入链上阶段后，所有标记为 `TESTNET`
的交易行为都必须通过 Injective Testnet，并以链上或 Indexer 结果为准。

当前架构基线明确为：

> **AI
> Town 是项目底座**，负责小镇世界、角色移动、对话、记忆、自治循环和前端可视化；**TwinMarket 是金融行为能力层**，提供投资者画像、行为金融参数、决策提示与评测方法；`MarketAdapter`
> 负责隔离本地模拟市场与 Injective Testnet。

不使用 TwinMarket 替换 AI
Town，也不把 TwinMarket 的 Python 主循环或本地撮合器作为产品主运行时。需要复用的 TwinMarket 能力通过 TypeScript 适配层接入 AI
Town，并保留上游版本、许可证、来源映射和契约测试。

适合现场演示的画面demo：

> “央行突然加息”出现 → 新闻社发布消息 → 不同 Agent 形成不同观点 → 恐慌在人际网络中传播 → 居民跑向交易所 → 卖单涌入 →
> K 线暴跌 → 输出一份模拟报告

## 2\.2 金融人格与行为层：TwinMarket

https://github\.com/FreedomIntelligence/TwinMarket

TwinMarket 是面向金融市场的多 Agent 社会与行为模拟项目。项目固定使用 commit


## 2\.3 模拟金融市场的引擎：Injective

### 简介和原理

Injective在区块链底层内置了一个 `exchange` 模块，相当于链本身就运行着一个公共交易所内核。

> 原生模块可以完整支持交易所和结算系统，我们只需接入即可。

文档：

https://docs\.injective\.network/developers\-native/injective/exchange

```Markdown
它能够负责：
- 创建模拟资产
- 创建交易市场
- 维护链上订单簿
- 接受挂单、吃单和撤单
- 自动撮合
- 冻结和结算资金
- 记录成交、持仓、余额和交易哈希
- 提供实时订单簿、成交和历史数据
```

> Injective 是金融小镇的“中央交易所 \+ 清算所 \+ 链上账本”，AI Town 是城市和居民系统。

产品概念中的本地模拟市场为：

```Markdown
ACME / TOWNUSD
```

其中，`ACME` 是金融小镇中的虚拟公司股票，`TOWNUSD`
是小镇里的模拟美元。价格代表购买一单位 ACME 所需的 TOWNUSD。Agent 必须拥有对应资产才能买卖。黑客松 Testnet 实盘路径则使用
`ACME/INJ`：TOWNUSD 继续服务本地模拟，链上使用已经具备交易所最小名义价值配置的原生 INJ，避免为自定义 TOWNUSD 申请额外的链参数注册。

> 黑客松项目只需要实现现货市场即可，因为没有杠杆和爆仓、不需要外部价格预言机、容易向评委解释、容易控制初始资产分配、交易和财富变化直观。

Injective 使用链上 CLOB，撮合发生在每个区块结束阶段。采用 Frequent Batch Auction，即“频繁批量竞价”。

```Visual Basic
Frequent Batch Auction：
一个区块内收集订单。市场单先与区块开始时已有的订单簿撮合。再处理新进入的限价单。批次内计算撮合和清算价格。成交结果写入区块状态。
```

它不是传统中心化交易所那种微秒级连续撮合，但是对于我们非常合适，因为居民不需要进行高频交易。可以让每个 Agent 每隔 10～30 秒产生一次决策，市场仍然会显得很活跃。

agent的资产管理：

可以用一个钱包，多个 Subaccount的方式，来为每个agent创建独立的账户。这样，只需要管理一个私钥，资金和订单仍然相互隔离，每个 Subaccount 在链上可区分，适合中心化控制的模拟实验。

### 怎么模拟

以一家虚拟公司 `ACME` 为例：

1. 在 Injective Testnet 创建一种 TokenFactory 代币：

   - `ACME`：虚拟公司股票

2. 使用原生测试币 INJ 作为报价资产，创建 `ACME/INJ` 现货市场。

3. 给每个 AI Agent 分配独立交易账户和初始资产，例如：

   - 做市商：大量现金和股票

   - 基金经理：较多资产，交易金额较大

   - 散户：资金较少，容易受情绪影响

   - 记者：掌握和传播新闻

   - 内幕交易者：提前获得部分信息

4. 新闻和社会事件改变 Agent 的观点。

5. Agent 产生买入、卖出或观望的意图。

6. agent将交易意图转换为具体价格和数量，并提交到 Injective。

7. Injective 负责检查余额、撮合订单、交换资产并记录交易。

8. 前端读取链上结果，展示人物行为、K 线、订单簿、财富变化和交易哈希。

完整链路：

> 新闻事件 → Agent 形成观点 → 提交订单 → Injective 链上撮合 → 价格和财富变化 → 小镇可视化

## 2\.4 金融决策 Agents 的记忆机制

Graphiti 集成方案： https://github\.com/getzep/graphiti

1. 架构定位

原来设计的记忆系统是 Stanford Smallville 风格的 Memory
Stream（观察 → 反思 → 规划），用 recency/importance/relevance 评分检索。

Graphiti 在后续阶段增强这一层，但不替换 AI Town 第一阶段已有的角色记忆与对话状态：

原方案: 文本记忆流 \+ FAISS向量检索 \+ 手动评分

新方案: Graphiti 知识图谱 \+ 时间感知 \+ 混合搜索

核心优势：Graphiti 自动从对话/事件中提取实体和关系，构建动态图谱，天然适合金融市场中"谁影响了谁"、"什么事件导致了什么结果"这类因果链。

2. 技术栈调整

| 组件     | 原方案             | 调整                                      |
| -------- | ------------------ | ----------------------------------------- |
| 记忆存储 | FAISS \+ SQLite    | Graphiti \+ FalkorDB（或 Neo4j）          |
| 记忆检索 | 向量相似度         | Graphiti 混合搜索（图遍历\+语义\+关键词） |
| LLM      | Qwen3\-8B \(vLLM\) | 不变，Graphiti 通过 OpenAI 兼容接口调用   |

推荐用 FalkorDB（比 Neo4j 轻量，Redis 协议，Docker 一行启动）：

docker run \-p 6379:6379 \-p 3000:3000 \-it \-\-rm falkordb/falkordb:latest

核心代码结构

```Python
投资理财策略模拟顾问/
├── src/
│   ├── memory/
│   │   ├── __init__.py
│   │   ├── graphiti_memory.py    # Graphiti 封装层
│   │   └── schemas.py            # 实体/关系定义
│   ├── agents/
│   │   ├── __init__.py
│   │   ├── base_agent.py         # Agent 基类（含记忆接口）
│   │   ├── retail_trader.py      # 散户
│   │   ├── fund_manager.py       # 基金经理
│   │   ├── market_maker.py       # 做市商
│   │   ├── journalist.py         # 记者
│   │   └── insider.py            # 内幕交易者
│   ├── market/
│   │   ├── injective_client.py   # Injective 交互
│   │   └── order_manager.py      # 订单管理
│   ├── news/
│   │   └── event_engine.py       # 新闻/事件引擎
│   └── simulation/

│       └── report.py             # 模拟报告

├── requirements.txt

```

Graphiti 带来的关键收益

| 对比维度      | 原方案 \(FAISS\) | Graphiti                              |
| ------------- | ---------------- | ------------------------------------- |
| 记忆结构      | 扁平文本块       | 知识图谱（实体\-关系\-实体）          |
| 时间感知      | 手动实现         | 内置（自动追踪事实有效期）            |
| 因果推理      | 弱               | 强（"加息 → 恐慌 → 抛售"链路）        |
| 检索方式      | 仅向量相似度     | 混合（图遍历\+语义\+关键词）          |
| 记忆演化      | 需手动管理       | 自动（新信息合并/覆盖旧信息）         |
| 跨 Agent 关系 | 不支持           | 天然支持（图中直接建模 Agent 间关系） |

## 3.1 数据分工

| 数据层          | 主要职责                                                     |
| --------------- | ------------------------------------------------------------ |
| Scenario Engine | 控制 runId、随机种子、利率冲击、谣言/纠正和初始参考价        |
| PandaAI         | 提供 DayView、Agent 观点、社交传播、模拟账户、研究和风险复盘 |
| Injective       | 提供真实市场、订单簿、订单、成交、余额和链上凭证             |
| Finance Engine  | 确定性计算价格/数量、风控、成本、PnL、NAV 和 K 线            |
| Convex          | 保存数据，向 UI 提供统一查询、回放和证据关联                 |

> PandaAI 解释“为什么这样判断和交易”；Injective 证明“是否真的提交、撮合和结算”。

Panda 模拟成交及模拟 tx hash 不是链上事实，必须与 Injective 的 `txHash`、`orderHash`、`tradeId`

Engine 初始值和 Injective 成交，不能被 Panda 的外部股票行情覆盖。

## 3.5 A2A Remote Agent 对外服务方案

A2A 不另建独立产品或仓库，而是在当前 `trade-town` 中新增公开协议适配服务。Convex 和 Finance
Engine 负责业务能力，A2A 服务只负责 Agent 发现、任务管理和结果包装。

```text
trade-town/
├── convex/                           # 小镇、Run、证据链和业务数据
└── services/
    ├── injective-gateway/            # 私有签名与链上回流
    └── market-town-a2a/              # 公开 A2A Remote Agent
```

### 技术栈

| 模块       | 推荐技术                   | 职责                                        |
| ---------- | -------------------------- | ------------------------------------------- |
| A2A 协议   | 官方 `@a2a-js/sdk`         | Agent Card、消息、Task、Artifact 和协议错误 |
| HTTP 服务  | Node.js + Express          | 对外提供 HTTPS、JSON-RPC 和可选 SSE         |
| 数据与任务 | Convex                     | 保存任务状态、Run 关联和 Artifact           |
| 业务执行   | Scenario / Finance / Coach | 复用现有实验、证据链和复盘能力              |

| 接口                               | 用途                                  |
| ---------------------------------- | ------------------------------------- |
| `GET /.well-known/agent-card.json` | PandaAI 发现 Agent、协议版本和 Skills |
| `POST /a2a/v1`                     | 发送自然语言或结构化任务              |
| `GetTask`                          | 查询任务状态和最终 Artifact           |

当前已在 `services/market-town-a2a` 实现第一版：使用官方 SDK 同时兼容 A2A 1.0 与 v0.3，提供 Agent
Card、JSON-RPC、Task/Artifact、三个示例任务、Bearer 鉴权、限流，以及可选的 Convex 任务持久化。本地仅运行明确标记为
`simulated` 的确定性实验；本项目当前选择 DeepSeek V4
Pro，因此竞赛模式强制 HTTPS、DeepSeek 配置与 Convex 持久化。赛道规则也允许火山低延迟模型，如切换模型需同步调整配置校验和模型调用适配器。

| Skill ID                     | 能力                   | 主要输入                 | 主要输出                                     |
| ---------------------------- | ---------------------- | ------------------------ | -------------------------------------------- |
| `rate-shock-experiment`      | 运行“加息 100bp”实验   | scenario、seed、执行模式 | runId、关键证据链、链上凭证、风险结论        |
| `rumor-propagation-analysis` | 分析谣言传播和更正效果 | runId 或固定场景、seed   | 传播路径、观点变化、受影响订单、更正前后差异 |
| `user-behavior-review`       | 复盘用户数字分身行为   | runId、userProfileId     | 行为偏差、风险规则、两个可复算反事实         |

复杂任务使用 `SUBMITTED → WORKING → COMPLETED/FAILED` 状态，并在 Convex 新增 `a2aTasks` 和
`a2aArtifacts`。成功任务统一返回 `MarketTownReport`，包括
`runId`、场景版本、Seed、证据链、风险结论、反事实、链上凭证和风险提示。

- A2A 进程不读取 `INJECTIVE_PRIVATE_KEY`，也不向客户端暴露 `GATEWAY_SHARED_SECRET`；
- 只允许 Agent Card 中声明的三个白名单 Skills；
- 外部消息必须经过长度限制、Schema 校验、鉴权、限流和幂等检查；
- `live` 只在 Injective 链路正常时执行，历史数据使用 `verified-replay`；
- 不得使用 Preview Tx Hash、静态 K 线或模拟成交伪装真实任务成功。

实施顺序：

1. 定义 `MarketTownReport` 和三个 Skill 的输入输出 Schema；

4. 部署公开 HTTPS 服务，并向 PandaAI 注册 Agent Card；
5. 使用 A2A Inspector/TCK 和 PandaAI 实际调用验收。

完成标准：

- PandaAI 能访问 Agent Card 并调用三个 Skills；
- 三个任务均返回可解释的结构化 Artifact；
- 链上任务包含真实 Injective 凭证，复盘包含两个反事实；
- 服务重启后仍可查询任务，相同请求不会重复启动 Run；
- 失败、降级和模拟数据不会被误报为链上成功。
